# IKEA effect

## Mechanism

People value what they build more than an identical thing someone else made. A milder form, the endowment effect, needs no building at all: feeling that something is yours is enough. A signup form where the user has made nothing gives them nothing to lose by closing the tab.

## Bad screen

`Create Your Workspace` with a generic `+` placeholder icon, the line `Sign up to start building your custom workspace`, `Email` and `Password` fields, and a `Sign Up` button. The user is asked to commit before they have made anything.

## Good screen

The user builds before signing up. The screen says `Customize how you'll appear to others` and shows a live profile card:

- **Card content:** name (`Sarah Johnson`), title (`Product Designer`), and tags (`San Francisco`, `5 years exp`).
- **Color palette:** a row of swatches.
- **Card style:** tiles `Soft` (selected), `Dark`, and `Minimal`.
- **Button:** `Continue to sign up` instead of `Sign Up`.

Each choice makes the card feel more like the user's own, so the signup step is the natural way to keep it. A language app that lets the user pick a language, set a goal, and finish a first lesson before the account screen follows the same pattern.

## Rules

- Let the user create, choose, or configure something real before signup: a profile, a first project, a preference set, a first lesson.
- Show the result live as they build it.
- Label the signup step as a continuation (`Continue`, `Save my workspace`) rather than a gate.

## Limits

- Keep what the user built if they leave: store it locally or let them return to it. Do not use their work as a hostage.
- Ask only for choices that improve their product experience, not busywork that exists to create sunk cost.
