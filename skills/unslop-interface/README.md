## Overview

Interfaces generated by AI tools share a recognizable look: purple gradients, glow, emoji icons, gradient text, pill badges, "Welcome back!" headers, and gaps that follow no scale. The screen works, but it reads as a template.

Unslop Interface gives an agent a fixed order of eight passes, a checklist of the tells, and a concrete before and after for each pass. The agent inventories the tells, fixes them one pass at a time in the UI code (or describes exact changes for a screenshot), and reports what changed. The passes and measurements were distilled from the Damir Sokolovsky clip "Unslopping a vibecoded dashboard" with the Video to Skill skill, and the tabular figures rule for changing numbers from a clip by Nexvyn.

```text
  UI code or screenshot
          │
          v
  inventory the tells ──> references/quality/slop-tells.md
          │
          v
  spacing ─> radius ─> color ─> icons ─> type and copy ─> data display
          │            references/passes/0N-*.md
          v
  verify against the inventory
          │
          v
  unslop report (per pass before and after, files, tokens)
```

| This skill does | This skill does not |
|-----------------|---------------------|
| Remove decorative gradients, glow, emoji icons, and filler copy | Change what the screen asks the user to do |
| Normalize spacing, radius, icon alignment, and type | Audit accessibility or performance |
| Edit HTML, CSS, Tailwind, React, Vue, or Svelte code in place | Build a new screen from nothing |
| Reuse the project's tokens, icon set, and chart library | Add new visual trends in place of the old ones |

## Features

- **Ordered passes:** spacing, corner radius, color, icons and alignment, typography and copy, data display, actions and structure, and states and feel, each in its own reference file.
- **Taste files:** `~/.gti/unslop-interface/taste.md` and a per-project file list what the user bans and what to keep; bans become extra tells and keeps are never changed.
- **Native and Rust interfaces:** egui, iced, Slint, and gpui get the same passes, measured with screenshots, layout overlays, and a source scan that reads `.rs` and `.slint` colors.
- **Suggestions, not changes:** an icon library (Lucide, Phosphor, Font Awesome, Noto Emoji) is suggested in the report when the icons are hand-drawn; the skill never adds a dependency.
- **Shallow and full scope:** shallow fixes the screen you name with all its states; full maps every page from the routes in the source and a crawl of the running app (`crawl.mjs`), then reviews each page and state with a coverage table.
- **Before and after diff:** `snapshot.mjs` lists what changed per element ("radius 6 -> 14") with screenshots of both states.
- **Measured examples:** the spacing and icon passes include the exact values from the source frames, before and after, and the typography pass includes a measured timer that stops shifting with tabular figures.
- **Tells checklist:** one table of tells, each mapped to the pass that fixes it, used before and after the work.
- **Keeps the information:** every number, item, and action stays; only decoration and filler go.
- **Precise vocabulary:** the report names each fix with its UI term (affordance, leading, tabular numbers, sticky positioning).
- **Report template:** the screens and passes covered, before and after per pass, changed files, new tokens, and tells kept on purpose.
- **Measured before and after (added):** when the app runs, the bundled lintapple linter measures gaps, insets, radii, contrast, fonts, type sizes, tabular numbers, and banned copy in Chromium; findings join the inventory under the pass that fixes them, and the report shows counts before and after. Shared with Frontend Design Review through `packages/lintapple`.
- **Own CLI:** `scripts/unslop/unslop.mjs` turns "5 passes" into five full rounds, lists every screen in scope, scans templates for tells a class grep misses, and fails a report that skips a screen, a round, or a pass.
- **Works without tools:** from source code, a screenshot, or both; lintapple is used only when the app can run.

From the repository root, install the skill into any supported agent:

```bash
node packages/cli install --harness claude --skill unslop-interface
```

The same command works in PowerShell. Use a comma separated list or `all` for several agents, `--scope user` to install for every project, and `--dry-run` to preview.

## Quick Start

```text
Unslop src/pages/Dashboard.tsx. It looks too AI generated.
```

The agent lists the tells it finds, runs the eight passes in order on the component, and returns a report with before and after per pass and the files it changed.

## Usage

### Input

| Input | Required | Example |
|-------|:--------:|---------|
| Interface | Yes | A component file such as `Dashboard.tsx`, a page's HTML and CSS, or a screenshot |
| Design tokens | No | The project's spacing scale, radius, colors, font, and icon library |
| Scope | No | Only some passes ("just spacing and color"), a number of full rounds ("5 passes" runs all eight passes five times), or report without editing code |
| Theme | No | Keep light or dark; the skill keeps the current theme by default |



```text
Run only the color and typography passes on components/StatsCard.vue.
```

```text
Unslop the new task screens in 3 passes.
```

## How It Works

```text
  0. Start         unslop.mjs start: rounds, passes, and screens from the request
          │
  1. Inventory      unslop.mjs scan and strings, then list every tell, note existing tokens
          │
  2. Spacing        one scale, shared content edges
          │
  3. Radius         at most three radii, no pill inputs
          │
  4. Color          neutral base, color only for meaning
          │
  5. Icons          one icon set, one column, dots for categories
          │
  6. Type and copy  calm weights, sentence case, numbers with context, tabular figures
          │
  7. Data display   labeled axes, colors that match a key, dashboards with context
          │
  8. Actions        one primary per view, forms out of list items
          │
  9. States         skeletons, optimistic updates, undo, motion, focus
          │
 10. Verify         re-check the inventory, diff the snapshots, write the report,
                    unslop.mjs check until it passes
          │
  repeat 2 to 10 for every round the request asked for
```

## Reference

### Pass files

Each file holds the goal, the before and after from the source, steps, and a check. The agent reads a file only when it reaches that pass.

| File | Pass | Typical fixes |
|------|------|---------------|
| `references/passes/01-spacing.md` | Spacing | Arbitrary gaps snapped to a scale, aligned content edges |
| `references/passes/02-radius.md` | Corner radius | Pills replaced, radius tokens |
| `references/passes/03-color.md` | Color and effects | Gradients, glow, and tinted glass removed |
| `references/passes/04-icons.md` | Icons and alignment | Emoji replaced by a line icon set, fixed inset and gap, actions given affordance |
| `references/passes/05-typography-and-copy.md` | Typography and copy | Caps, exclamation marks, filler headers, and redundant page taglines removed; tabular figures for changing numbers; body leading and ligatures |
| `references/passes/06-data-display.md` | Data display and dashboards | Axes, units, colors tied to a legend, sticky table headers, tables for compared records, and dashboards: four to six KPIs with context, chart choice by data, date range, and states |
| `references/passes/08-states-and-feel.md` | States and feel | Skeletons and image placeholders, optimistic updates, undo instead of confirm, motion, gestures, autofill, hover and focus |
| `references/passes/07-actions-and-structure.md` | Actions and structure | One primary per view, forms moved out of list items, advanced options folded in, state actions only in their state |
| `references/quality/slop-tells.md` | Checklist | Every tell mapped to its pass |
| `references/quality/vocabulary.md` | Vocabulary | Precise UI terms to name each fix in the report |
| `references/quality/taste.md` | Taste files | Format and use of the user's Ban and Keep lists |
| `references/lintapple/lintapple.md` | Measured checks | Running lintapple, adapting its policy, reading findings (shared with Frontend Design Review) |

### scripts/unslop/unslop.mjs

The skill's own CLI. It plans the run from the user's words, inventories the screens from source, and checks that the report covers every screen, round, and pass. It needs only Node.js and writes its run state to `~/.gti/unslop-interface/<project>/`.

```bash
node skills/unslop-interface/scripts/unslop/unslop.mjs start --repo . --request "unslop the new screens in 5 passes" --since origin/master
node skills/unslop-interface/scripts/unslop/unslop.mjs scan --run
node skills/unslop-interface/scripts/unslop/unslop.mjs strings src/views/TaskDetailView.vue
node skills/unslop-interface/scripts/unslop/unslop.mjs check ~/.gti/unslop-interface/<project>/report.md
```

| Command | Purpose | Key flags |
|---------|---------|-----------|
| `start` | Reads the request: a number of passes is a number of full rounds of all eight passes, and named passes limit the run only with "only" or "just". Lists the screens in scope and writes `run.json` | `--request`, `--rounds`, `--since <git ref>`, `--paths <files or folders>`, `--repo` |
| `scan` | Lists candidate tells in the source by pass, with file and line: narration, restated status, repeated values, raw IDs, enums, and JSON, empty rows and counters, equal card grids, copy buttons everywhere, cut off paths, native controls next to the project's own, destructive actions not in danger style, refresh on live pages, disabled controls with no reason, async actions with no busy state, gradients, tracked caps, and emoji. Writes `scan.json` next to the run | `--run [run.json]`, files or folders, `--json` |
| `strings` | Prints every visible string and rendered value of one screen in order, with how often each repeats | `--json` |
| `check` | Fails (exit 1) when the report has no coverage section, misses a screen in scope, a round, or a pass, skips a pass with no reason or because of the number in the request, or skips a pass that still has scan candidates | `--run <run.json>` |

### scripts/lintapple/probe.mjs

Measures layout problems that need no `data-ui-*` markers, and colors that match no token. Shared with Frontend Design Review and synced from `packages/lintapple/agent`.

```bash
node skills/unslop-interface/scripts/lintapple/probe.mjs http://localhost:3000 --project <app folder>
```

| Argument | Default | Description |
|----------|---------|-------------|
| `<url>` | Required | The running page: a dev server, preview URL, or `file://` page |
| `--project` | Current folder | Folder whose `node_modules/playwright` is used before the gti-skills copy |
| `--viewport WxH` | `1440x900` and `390x844` | Viewport to probe; repeat for several |
| `--ready` | None | Selector to wait for before measuring |
| `--ignore` | Maps, SVG, `[role=application]` | Extra selector to skip |
| `--near` | `12` | Largest edge offset reported as a near miss, in pixels |
| `--lane` | `64` | Largest distance to a shared column edge reported as off-lane, in pixels |
| `--json` | Off | Print every finding as JSON |

Rules: `near-miss-edge`, `off-lane`, `ragged-wrap`, `uneven-gap`, `curved-accent`, `nested-accent`, `uneven-siblings`, `misaligned-parts`, `repeated-form`, `competing-primaries`, `repeated-item-text`, `underlined-control`, `filters-outweigh-items`, `duplicate-filter`, `filter-link-in-item`, `empty-list-without-message`, `open-create-form`, `ragged-form-labels`, `raw-json-field`, `enum-as-text`, `unexplained-control`, `icon-column`, `toolbar-center`, `create-as-item`, `user-as-text`, `icon-source` (suggestion), `status-actions-apart`, `header-controls-below-title`, `behavior-footnote`, `repeated-value`, `stacked-output-panels`, `truncated-without-tooltip`, `kpi-without-context`, `too-many-kpis`, `chart-without-labels`, `arrow-suffix`, `accent-word`, `inconsistent-empty-copy`, `repeated-heading`, `lonely-word`, `transition-all`, `no-hover-state`, `no-pointer-cursor`, `off-token-color`.

| `--compare FILE` | None | Earlier capture to diff against |
| `--out DIR` | `~/.gti/lintapple/<project>/snapshots` | Output folder |

### scripts/lintapple/crawl.mjs

Maps every page of the running app for full scope: follows the links each rendered page shows, groups URLs into route patterns, visits one sample per pattern, and lists the states to review on each page. Shared with Frontend Design Review and synced from `packages/lintapple/agent`.

```bash
node skills/unslop-interface/scripts/lintapple/crawl.mjs http://localhost:3000
node skills/unslop-interface/scripts/lintapple/crawl.mjs http://localhost:3000/admin --storage-state ~/.gti/lintapple/<project>/admin-state.json --max 300
```

| Argument | Default | Description |
|----------|---------|-------------|
| `<url>` | Required | The first page; the crawl stays on its origin |
| `--max N` | `200` | Most route patterns to visit |
| `--depth N` | `6` | Most link hops from the first page |
| `--storage-state FILE` | None | Playwright storage state for pages behind a login |
| `--include REGEX` | None | Visit only URLs that match |
| `--exclude REGEX` | None | Skip URLs that match |
| `--keep-query` | Off | Treat URLs with different query strings as different pages |
| `--out DIR` | `~/.gti/lintapple/<project>` | Folder for `pages.md` and `pages.json` |
| `--project` | Current folder | Folder whose `node_modules/playwright` is used first |
| `--json` | Off | Print the result as JSON |

## Output

````markdown
# Unslop report: Overview dashboard

## Inventory

- **Source:** src/pages/Dashboard.tsx
- **Existing tokens reused:** Tailwind spacing scale, Lucide icons
- **Tells found:** purple gradient background, gradient heading, emoji nav icons,
  pill badges, "Welcome back!" title, "+12%!!"

## Passes

### 5. Typography and copy

- **Before:** "Welcome back, Damir!" bold gradient title; "+12%!!" with a fire emoji.
- **After:** "October 2026" regular weight; "+12% vs last month".
- **Files:** src/pages/Dashboard.tsx
````

| Section | Contents |
|---------|----------|
| Inventory | Source, reused tokens, and the tells found |
| Coverage | Every screen in scope, the rounds run, and each of the eight passes with the reason when it was skipped |
| Passes | One block per pass that changed something: before, after, files |
| Tokens introduced | New tokens with their values and use |
| Kept on purpose | Tells left in place and why |
| Not covered | Issues outside the scope, such as flows or accessibility |

The template is `assets/templates/unslop-report.md`.

## Troubleshooting

<details>
<summary><strong>lintapple says Chromium is missing</strong></summary>

Playwright's browser is not installed. Run the command the runner prints, for example:

```bash
cd packages/lintapple && npx playwright install chromium
```

</details>

<details>
<summary><strong>lintapple reports every font and size as wrong</strong></summary>

The default policy expects Apple system fonts and a fixed type scale. Write it out, set `fonts`, `fontSizes`, and `typeRules` to the project's design system, and pass it with `--config`:

```bash
node skills/unslop-interface/scripts/lintapple/run.mjs --write-policy ~/.gti/lintapple/<project>/ui-policy.json
```

</details>

<details>
<summary><strong>The agent does not see the skill</strong></summary>

Restart the agent session after installing, and confirm the folder is in the path your agent reads (see the table in [Installation](#installation)).

</details>

<details>
<summary><strong>The result switched my light theme to dark</strong></summary>

The source example ends on a dark theme, but the skill keeps the current theme by default. Say "keep the light theme" in the request, and the color pass builds the neutral ramp on light surfaces.

</details>

<details>
<summary><strong>The agent removed my brand color</strong></summary>

The color pass keeps one brand accent. Name the brand color or point to the token in the request, and the agent keeps it and lists it under "Kept on purpose".

</details>

<details>
<summary><strong>The agent wants to add an icon library</strong></summary>

The icons pass uses the project's icon library first and asks before adding a dependency. Name the library you want, or ask for inline SVG.

</details>

## Limitations

- The Damir Sokolovsky clip is silent. The pass order and measurements come from the frames; the reasons and general rules are written for this skill.
- Reviews from a screenshot cannot see hover, focus, loading, or responsive states.
- lintapple measures only a running page, and measures layout gaps, alignment, and radii only on elements marked with `data-ui-*` attributes or policy selectors.
- The skill polishes look and copy, not flows, conversion, or accessibility.
- Chart changes depend on the data the screen actually has; the agent cannot invent a new series.
- `unslop.mjs scan` reads Vue, Svelte, JSX, TSX, Astro, and HTML templates with patterns, not a parser: its findings are candidates to confirm on the screen, and it cannot see values that are equal only at runtime.
