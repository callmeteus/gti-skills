# The three quality pillars

Use this file in Mode 1 steps 4 and 5. Evaluate every pillar, even when one has no findings: write "no issues" for it in the report.

## Core principles

- **Task completion:** minimum clicks. Every screen answers "What can I do?" and "What happens next?"
- **Action hierarchy:** one or two primary actions per view. Secondary actions use progressive disclosure.
- **Onboarding:** explain a feature when it is introduced. Prefer smart defaults over configuration.
- **Navigation:** clear entry and exit points. Back or cancel is always available. Deep flows have breadcrumbs.

## 1. Frictionless insight to action

**Evaluate:**

- Can the user task be completed in three interactions or fewer?
- Is the primary action obvious, and is there only one?
- After each step, does the screen say what happens next?

**Red flags:** excessive clicks, several competing primary buttons, actions buried in menus or below the fold, dead ends with no next step, no way back or out.

## 2. Quality is craft

**Evaluate:**

- **Design system compliance:** matches the Figma specs and uses tokens. See [design-system.md](design-system.md).
- **Aesthetic direction:** distinctive typography, a cohesive palette, intentional motion. Generic AI aesthetics come from the Unslop Interface inventory.
- **Accessibility:** grade it with the table below.

**Red flags:** generic AI aesthetics, hardcoded values, an implementation that does not match Figma, broken reflow at 320px width or 400% zoom, missing focus indicators.

### Accessibility grade

| Grade | Meaning | Verdict |
|-------|---------|---------|
| B | Meets WCAG 2.1 AA | Ideal |
| C | Meets WCAG 2.1 A, fails some AA criteria | Minimum to ship |
| Below C | Fails at least one WCAG 2.1 A criterion | Blocking |

Check at least: text contrast (AA: 4.5:1 for body text, 3:1 for large text and UI parts), visible focus, keyboard access to every action, labels on form fields and icon buttons, alternative text on meaningful images, reflow without horizontal scroll at 320px, and no information carried by color alone. Name the WCAG success criterion in every accessibility finding. A review from screenshots cannot grade keyboard access or screen reader output; say so.

## 3. Trustworthy building

**Evaluate:**

- **AI transparency:** content generated by AI carries a visible disclaimer next to it.
- **Error transparency:** every error message says what happened and what the user can do next.

**Red flags:** AI output shown as fact with no disclaimer, opaque errors such as "Something went wrong" with no guidance, silent failures.

## Severity

| Severity | Rule | Examples |
|----------|------|----------|
| Blocking | The user cannot complete the task, or the UI fails WCAG 2.1 A | Dead end, unreachable action by keyboard, missing form labels |
| Major | The task completes with clear friction, confusion, a trust gap, or a broken design system contract | Two primary buttons, missing error state, opaque error, AI content with no disclaimer, custom duplicate component |
| Minor | Polish that does not block or confuse | A hardcoded value with a token, a slop tell in decoration, a small Figma drift |

When unsure between two levels, pick the lower one and say why.
